# BoxAI 生图交付问题与平台配置说明

更新时间：2026-11-17

## 1. 一句话结论

当前网站的生图业务流程、用户次数保护和支付宝核销逻辑正常。主要故障发生在 BoxAI 已经生成图片之后：BoxAI 向网站返回图片结果时，网络连接偶尔被重置，导致网站没有收到图片；同时 BoxAI 暂未提供按请求 ID 重新取回结果的接口。

这不是“网站不会调用 BoxAI”，而是“网站目前无法保证每一次都能完整收到 BoxAI 的生成结果”。

## 2. 用户生成流程

正常流程如下：

1. 用户选择风格模板；
2. 用户输入文字、上传参考图，或同时提供两者；
3. 网站把模板私有提示词、用户输入、固定模型和固定尺寸发送给 BoxAI；
4. BoxAI 生成图片；
5. BoxAI 把图片数据或图片地址返回给网站；
6. 网站保存图片并向用户展示；
7. 图片成功交付后，网站才核销用户的支付宝创作次数；
8. 用户作品保留 24 小时，用户需要自行下载保存。

发生异常时，流程停在第 5 步：BoxAI 已经完成第 4 步并计费，但网站没有收到完整的图片结果，因此不能执行第 6 步，也不会执行第 7 步。

## 4. 为什么网站不能直接重试

`ECONNRESET` 只能说明连接断开，不能证明 BoxAI 没有生成图片。

如果网站收到断连后立即重新发送同一条生图请求，可能出现：

- BoxAI 再生成一张图片；
- BoxAI 再收取一次费用；
- 用户得到重复作品；
- 平台承担重复成本。

因此当前平台不会对 `ECONNRESET`、504 或 524 自动重发生图 POST。只有明确没有连接到 BoxAI 的 DNS 或连接建立失败，才允许进行一次安全重试。

## 5. 为什么暂时不能找回已经生成的图片

平台已经使用真实 BoxAI 请求 ID，无费用测试以下可能的结果查询接口：

- `/v1/images/generations/{id}`
- `/v1/images/{id}`
- `/v1/generations/{id}`
- `/v1/tasks/{id}`
- `/v1/responses/{id}`

BoxAI 全部返回 404。当前公开 API 没有提供按请求 ID 重新获取图片结果的能力。

要彻底解决问题，BoxAI 需要提供以下至少一种能力：

1. 更稳定的同步图片响应；
2. 异步生图任务：先返回任务 ID，网站随后轮询结果；
3. 按 BoxAI 请求 ID 查询并下载已生成图片；
4. Webhook 回调，在图片生成完成后主动通知网站；
5. 幂等键，同一个业务请求重试时只生成和计费一次。

## 6. 平台现有保护措施

- 没有收到并保存图片时，不核销用户的支付宝创作次数；
- 不盲目重试可能已经被 BoxAI 执行的生成请求；
- 生成成功后才向创作者发放模板使用收益；
- BoxAI 结果下载阶段允许安全重试，但不重复提交生图任务；
- 用户上传素材和生成作品只保留 24 小时；
- 已增加结构化生产日志，不记录 API Key、私有提示词或用户图片。

结构化日志记录：

- 平台任务 ID；
- 模型名称；
- 输出尺寸和数量；
- 图片生成或图片编辑接口；
- 收到响应头的耗时；
- HTTP 状态；
- BoxAI 请求 ID；
- 响应类型和响应长度；
- 网络错误代码。

## 7. 当前模型配置

平台支持两个 BoxAI 模型：

- `gpt-image-2.5-flare`
- `gpt-image-2.5-sunburst`

模型按模板固定，不会在两个模型之间随机切换。管理员创建或编辑模板时选择模型，用户不能修改。

删除 7 个占位演示模板后，生产环境当前共有 8 个正式模板：

- `flare`：8 个；
- `sunburst`：0 个。

当前正式模板全部调用 `flare` 的原因是一键导入页面之前默认选择 `flare`，不是 `sunburst` 接入失败；平台仍支持在创建或编辑模板时明确选择 `sunburst`。

平台现已取消无效模型静默回退：如果模板模型名称错误，后台直接拒绝保存，调用层也不会偷偷替换成 `flare`。

后台模板导入另行接入 3 个 BoxAI 文本模型，用于把原始素材整理为待人工审核的模板草稿。它们与图片模型共用 `BOXAI_BASE_URL` 和 `BOXAI_API_KEY`，按以下固定顺序失败切换：

1. `deepseek-v4.1-flash`
2. `gemini-3.8-flash`
3. `gpt-6-luna`

文本模型只负责生成草稿，不会自动发布。草稿包括中英文标题和公开文案、分类、标签、建议比例和输入方式、服务端私有提示词及负面约束；管理员仍需在后台确认素材权利、图片和全部字段。所有模型都失败时可使用原有的本地规则整理，不会把原始素材、私有提示词或 API Key 写入结构化日志。

## 8. 当前高清尺寸配置

后台新建模板和一键导入模板默认使用 BoxAI 支持的“高清”档，不默认使用成本更高、耗时更长的“超清”档。

当前生产模板尺寸：

| 比例 | 高清尺寸 |
| --- | --- |
| `3:4` | `1536 × 2048` |
| `2:3` | `1536 × 2304` |
| `1:1` | `2048 × 2048` |
| `4:3` | `2048 × 1536` |

一键导入后台已经开放标准、高清、超清尺寸选择，并且会真实提交所选尺寸，不再因为缺少尺寸字段自动回落到标准尺寸。

高清通常会增加 BoxAI 生成耗时和调用成本。此前使用标准尺寸仍然发生约 30 秒连接重置，因此本次故障并不是由高清尺寸直接造成的。

## 11. 后续决策原则

- 在 BoxAI 提供结果恢复或幂等能力前，不自动重发断连请求；
- 不把 BoxAI 控制台的“成功”直接当作用户已收到作品；
- 只有平台保存图片并成功交付后，才核销用户次数和发放创作者收益；
- 如果 BoxAI 长期无法提供稳定交付能力，需要评估增加第二家生图供应商或直接接入原厂模型 API。
